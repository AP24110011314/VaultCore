# Database

PostgreSQL 16 in production and Docker; H2 in tests. The schema is generated by Hibernate from the entities
(`spring.jpa.hibernate.ddl-auto=update`), so the entity annotations ARE the schema definition.

## Entity relationship

```
assets 1 ---- * accounts * ---- 0..1 users
                  |
                  1
                  |
                  * 
            ledger_entries * ---- 1 transactions
```

## Tables

### assets
| Column | Type | Constraints |
|---|---|---|
| id | UUID | PK, generated by the application |
| name | VARCHAR(50) | NOT NULL |
| code | VARCHAR(50) | NOT NULL, UNIQUE |
| created_at | TIMESTAMPTZ | NOT NULL |

### users
| Column | Type | Constraints |
|---|---|---|
| id | UUID | PK |
| name | VARCHAR(100) | NOT NULL |
| email | VARCHAR(255) | NOT NULL, UNIQUE |
| created_at | TIMESTAMPTZ | NOT NULL |

### accounts
| Column | Type | Constraints |
|---|---|---|
| id | UUID | PK |
| user_id | UUID | FK to users, NULL for SYSTEM accounts |
| asset_id | UUID | FK to assets, NOT NULL |
| type | VARCHAR(10) | NOT NULL, `USER` or `SYSTEM` |
| balance | BIGINT | NOT NULL (cached; ledger is the source of truth) |
| created_at | TIMESTAMPTZ | NOT NULL |

Unique: `(user_id, asset_id)`: a user has at most one account per asset.
A database cannot easily enforce "exactly one SYSTEM account per asset" (NULLs are distinct in a unique constraint),
so that invariant is maintained by `DataSeeder` and must be preserved by any operational tooling.

### transactions
| Column | Type | Constraints |
|---|---|---|
| id | UUID | PK |
| type | VARCHAR(20) | NOT NULL, `TOPUP` / `BONUS` / `SPEND` |
| idempotency_key | VARCHAR(100) | NOT NULL, **UNIQUE** |
| status | VARCHAR(10) | NOT NULL, `SUCCESS` / `FAILED` |
| created_at | TIMESTAMPTZ | NOT NULL, indexed |

### ledger_entries
| Column | Type | Constraints |
|---|---|---|
| id | UUID | PK |
| transaction_id | UUID | FK to transactions, NOT NULL, indexed |
| account_id | UUID | FK to accounts, NOT NULL, indexed |
| type | VARCHAR(10) | NOT NULL, `CREDIT` / `DEBIT` |
| amount | BIGINT | NOT NULL, always positive |
| balance_after | BIGINT | NOT NULL, the account balance right after this entry |
| created_at | TIMESTAMPTZ | NOT NULL |

Ledger entries are append-only: all columns are mapped `updatable = false` and nothing deletes them.

## Conventions

- **Amounts are whole units** (`BIGINT` / Java `long`). Gold Coins, Diamonds and Points are indivisible, so there is no
  floating-point or decimal rounding.
- **Sign convention.** A `CREDIT` increases an account's balance, a `DEBIT` decreases it. For any account:
  `balance = SUM(CREDIT amounts) - SUM(DEBIT amounts)`.
- **Timestamps** are `Instant`, truncated to microseconds so the value returned on the first call equals the value
  read back from PostgreSQL on a replay.

## Invariants (verified by the tests)

1. Every transaction has exactly two ledger entries; total debits equal total credits.
2. For every account, `accounts.balance` equals the net of its ledger entries.
3. The sum of `accounts.balance` over all accounts is 0.
4. A USER account's balance is never negative.
5. An idempotency key maps to at most one transaction.

## Seed data

Created by `config/DataSeeder` (idempotent). Opening balances are TOPUP transactions with the fixed idempotency keys
`seed-aditi-gold` (500) and `seed-priya-gold` (300), so they leave ledger entries and a Treasury balance of -800.

| Entity | Rows |
|---|---|
| assets | GOLD_COINS, DIAMONDS, LOYALTY_POINTS |
| users | Aditi Singh (`aditisingh@gmail.com`), Priya Jha (`priyajha@gmail.com`) |
| SYSTEM accounts | one per asset |
| USER accounts | Aditi and Priya, each with GOLD_COINS and DIAMONDS |

## Useful audit queries

```sql
-- Cached balance vs ledger (should return no rows)
SELECT a.id, a.balance, COALESCE(SUM(CASE WHEN le.type = 'CREDIT' THEN le.amount ELSE -le.amount END), 0) AS ledger
FROM accounts a LEFT JOIN ledger_entries le ON le.account_id = a.id
GROUP BY a.id, a.balance
HAVING a.balance <> COALESCE(SUM(CASE WHEN le.type = 'CREDIT' THEN le.amount ELSE -le.amount END), 0);

-- Whole system balances to zero (should return 0)
SELECT COALESCE(SUM(balance), 0) FROM accounts;
```
